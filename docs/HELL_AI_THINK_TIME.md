# 公开 GitHub Pages：地狱 AI 思考时间策略

日期：2026-10-14
状态：设计与离线基准，不代表已在网页上线。

## 玩家体验目标

地狱 AI 可以明显花时间思考，但玩家的棋盘必须继续响应。
建议使用 Web Worker 异步搜索；玩家可随时停止思考、悔棋、重开、切图。
每次请求携带 gameId、turnId、map hash；迟到结果不得应用到新的回合。

### 默认思考档位（目标；真机实测后定稿）

| 局面 | 建议计算预算 |
| --- | ---: |
| 明确一步取胜 | 立即返回 |
| 普通局面 | 1,200 毫秒 |
| 双方进入中盘 | 2,200 毫秒 |
| 面临对手一步致胜或关键封锁 | 4,500 毫秒 |
| 复杂战术 | 5,000 毫秒 |
| 极端局面上限 | 6,000 毫秒 |

这是 **最大计算预算**，不是人为等待时长：已找到必胜行动可立即返回。
Web Worker 中定期报告最优合法行动和进度；超时使用最后已完成深度的合法方案。
Worker 启动不可用时降级为既有原生 AI，不把多秒搜索放进浏览器 UI 主线程。

## 棋力评测

- 公平比较：挑战者和冻结基线必须使用相同计算预算（例如 850ms、1500ms、3000ms），且双方交换执棋。
- 需要独立保留测试地图；同一组地图调参后不能再次用作最终盲测。
- 战术测试保持 100% 的必胜/必防正确率和 0 非法行动。
- 统计 500 张地图、1000 局换手后的成对 bootstrap 95% 区间，且置信下界超过 50%，才能进入网页候选名单。
- 即使 Node.js 对局胜出，仍要测试 iPhone Safari / Android Chrome：思考过程不卡界面、超时落子可靠、内存增长可控。

220ms 深度 2：V2 在 200 局对 V1.1 得分 103:97，95% 区间 [48.5%, 54.5%]，未晋级。
440ms 深度 3 对 V1.1 深度 2：40 局 25:15，95% 区间 [50%, 75%]，样本不足，且仍存在深度/有效资源利用上的差异。
850ms 深度 3：60 张地图、120 局双方换手，V2 59 胜 / 61 负，49.17%；成对地图 Bootstrap 95% 区间 [40.0%, 57.5%]；0 非法行动、120 次目标胜利。**高预算下未战胜 V1.1**。这一测试与过去测试使用了相同代码规则，不能据此证明 V2 更强；不允许将 V2 替换线上。
