# 哦，木木金金棋：下一阶段规划与验收标准

更新：2026-10-13

## 1. 已交付：稳定底座

- GitHub Pages 静态部署、手机单屏棋盘与固定操作条。
- 9×13 地图、本地双人、移动、筑墙、传送门、悔棋、胜负。
- 传送门计入筑墙可达性；进阶冰面使用“格子 + 方向”作为路径状态。
- 自动测试：smoke、portal-regression、ice-regression。

## 2. 人机对战（M1：已实施首版，仍需真实玩家持续试玩）

不依赖 DeepSeek / GLM / 在线模型：在浏览器端运行规则 AI，离线也能对局。
人类执金方，电脑执木方（包括出生点自动选择）。

三个梯度：

1. **入门**：优先朝目标营地前进，保留少量随机移动，不主动筑墙。
2. **策略**：估计双方到目标的回合数，只有筑墙能显著延长玩家路线时才考虑筑墙。
3. **挑战**：更积极寻找限制路线的墙；对传送/冰面/加速仍遵守实际规则。当前只是启发式策略，不宣称精确最优或不可战胜。

### M1 验收

- [x] 双人、人机两种方式相互隔离。
- [x] 电脑自动选择出生点、移动或合法筑墙。
- [x] 三种难度可切换，切换后确认重置。
- [x] 人机模式悔棋撤销完整一对行动。
- [x] 复用真实移动和墙的规则，不可越墙、踩障碍或封死去路。
- [x] 旧版双人、传送门和冰面回归测试通过。
- [x] 规则引擎完成 60 回合自动模拟，覆盖三档难度与两种地图模式。
- [x] 390×844 手机模拟浏览器测试：选择人机、切换挑战、自动出生、电脑筑墙、无上下滚动、零脚本异常。
- [ ] 真实用户试玩 30 局（覆盖经典、跑道、狭窄通道、传送后的选择），记录异常与无动作回合。
- [ ] 在真实手机上对高难度耗时进行抽样（目标单回合计算 < 300ms）。

> 后续如想加入真正更强的 AI，可再考虑 beam search（束搜索）/ minimax（极小极大搜索）及状态缓存；不宜直接用大模型逐步读图下棋，因为延迟、稳定性和费用更差。

## 3. 地图工坊（M2：方案阶段；未作为现成游戏功能发布）

**建议不要以“换皮肤”名义实现地图编辑。** 地图是规则数据，不是单纯换背景。

### 最小可用版本

1. 从经典地图复制一个草稿；切换编辑/试玩两种状态。
2. 优先允许新增、移动、删除 **固定障碍物**，可一键还原原始地图。
3. 固定营地和三组传送门；暂不允许任意改出生点或重连传送门。
4. 提供撤销、保存到浏览器、导出/导入 JSON。
5. 每次编辑提供明确合法性校验：越界、覆盖出生区/传送格、位置重叠、双方是否仍有可到达对方营地的路径。
6. 只有通过校验才能开始在该地图上对弈。

### 推荐地图 Schema v1

```json
{
  "version": 1,
  "size": {"cols": 9, "rows": 13},
  "name": "我的第一张地图",
  "rocks": [{"x": 3, "y": 2}],
  "terrainPreset": "classic"
}
```

编辑配置只覆盖 rocks；camp/portal/ice/boost 从官方模板加载，避免首版把地图编辑和规则重构捆在一起。

### M2 验收

- [ ] 禁止覆盖任一出生点/传送门、禁止坐标越界和重复障碍。
- [ ] 自定义地图不允许生成两边无法获胜的初始死局。
- [ ] 支持撤销/恢复默认/导出/导入；异常 JSON 不得破坏已有草稿。
- [ ] 9×13 棋盘在手机上编辑时不需要页面上下滑动。
- [ ] 默认双人和人机都能使用已保存且校验通过的自定义地图。
- [ ] 重新打开浏览器后，用户自行保存的地图仍可读取。

## 4. 规则设计问题（待与原作者确认）

- 冰面：当前是“每回合前方可走则继续同方向；若受阻可转向”，而非一次滑到冰面尽头。
- 传送门：玩家可以选择传或不传；过门不额外消耗回合。
- 方向锁：传送到出口后清空之前的冰面惯性。
- 电脑走棋：当前固定电脑为木方。
- 经典赛事建议：仍默认 **本地双人 + 经典战场**，进阶/人机不替代稳定的核心规则。

## 5. 实施优先级

M1 人机 MVP / 回归 -> M2 障碍物编辑器 -> M3 分享地图 -> M4 高阶 AI（束搜索/小规模 minimax）。

**不要把“AI 三个名字”等同于三种难度。** 难度必须体现在可衡量的选择质量与对手胜率，而不只是随机程度。
