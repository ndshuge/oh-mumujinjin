# 好友邀请直达与棋盘视觉重构 — 验收记录（2026-11-07）

## 已实现
- 默认联机线路改为 Supabase 国内试用；邀请码显式 `net=cf` 时保留 Cloudflare，不被默认覆盖。
- `?room=<六位码>&net=sb|cf` 打开即显示房间准备界面、自动连线；正确的房间状态来自后端而非客户端伪造。网络失败显示清楚的失败状态、保持房间码，并提供「重新连接房间」。
- 等待界面隐藏不必要的地图标签，玩家可见房间码、地图、双方准备状态、邀请链接与准备按钮。
- 地图中心顶部新增「＋ 创建地图」，进入现有地图工坊并清空**草稿**的可编辑层，保留固定营地及全部已保存地图。工坊可绘制、命名和保存，保存后自动出现在「我的地图」。
- 棋盘内两方棋子替换为原创 Canvas 圆润高光棋子（小表情、立体底座），显示坐标独立于逻辑坐标；坐标变化时 240ms cubic easing + 轻微离地反馈，系统 Reduced Motion 下立即定位，无无限空转动画。

## 已验证
- 真实 Supabase 网络 + Chrome 手机尺寸 E2E：邀请自动加入、准备按钮可用、准备同步到房主。两个独立 WebSocket。
- 真实 Chrome 浏览器：从地图中心创建空白地图 → 进入工坊 → 命名保存 → 地图列表可再次读出。
- 现有 `browser-smoke.mjs`：大厅、地图收藏/重命名、AI、本地开局、响应式回归通过。
- Canvas 390×844 视口实画面检查：双方棋子成功出现并和盘面图层正常组合。
- 新增静态/结构回归测试 8/8，通过；房间/地图重点回归 19/19，通过；完整 `node --test` 存在历史 `training/puct-test.cjs` 偶发 `No valid map 0`，**该失败不属于好友房间或本次 UI 改动**，不能宣称完整测试 100% 通过。

## 未实现/交付边界
- 当前 Supabase 仍是房主浏览器权威。房主下线后不可继续对局；消除该限制需要服务端持久化游戏状态、校验和玩家鉴权，属于另一个后端工程。
- 参考 Duolingo Chess 的圆润、清晰、短弹性动画体验，未使用/复制其专有棋子图像与品牌素材，不能称为素材级 1:1 复刻。
- 仍需两台真实手机、特别是中国大陆两位玩家无 VPN 的网络与 Safari/Android 流畅度最终确认。
